HIGGSFIELD BENZERİ AI PLATFORMU — ANA MİMARİ SÖZLEŞMESİ

Bu belge projenin en üst seviye teknik mimari talimatıdır.

Bu projede herhangi bir özellik geliştirilmeden, provider bağlanmadan, veritabanı tablosu değiştirilmeden veya mevcut kod yeniden düzenlenmeden önce bu kurallar dikkate alınmalıdır.

Amaç, Higgsfield benzeri çok modelli bir AI görsel ve video üretim platformu kurmaktır. Ancak başka bir şirketin özel kodu, ticari sırrı veya bilinmeyen iç altyapısı taklit edilmeyecektir. Yalnızca gözlemlenebilen ürün davranışları temel alınarak bağımsız ve sürdürülebilir bir sistem geliştirilecektir.

5. MODEL REGISTRY TEK GERÇEK KAYNAK OLMALIDIR

Platformda desteklenen bütün modeller merkezi bir registry içinde tanımlanmalıdır.

Örnek:

type ModelDefinition = {
  key: string;
  displayName: string;
  provider: string;
  providerModelId: string;
  adapter: string;

  capabilities: {
    textToImage: boolean;
    imageToImage: boolean;
    textToVideo: boolean;
    imageToVideo: boolean;
    videoToVideo: boolean;
    audio: boolean;
    lipSync: boolean;
  };

  limits: {
    durations?: number[];
    aspectRatios?: string[];
    maxReferenceImages?: number;
    maxPromptLength?: number;
    supportedResolutions?: string[];
  };

  pricing: {
    internalCreditCost: number;
    estimatedProviderCost?: number;
  };

  availability: {
    enabled: boolean;
    maintenanceMode: boolean;
    allowedPlans: string[];
  };
};

Frontend’de elle yazılmış ayrı model listeleri oluşturulmamalıdır.

Model listesi backend registry’den alınmalıdır.

Model kartı, fiyat, desteklenen süre, çözünürlük ve en-boy oranları aynı registry verisinden üretilmelidir.

6. PROVIDER ADAPTER KURALI

Her sağlayıcı ayrı adapter kullanmalıdır.

providers/
  fal/
  runway/
  google/
  kling/
  replicate/
  cloudflare/

Her adapter aşağıdaki temel işlemleri standart biçimde sunmalıdır:

interface GenerationProviderAdapter {
  validateInput(input: NormalizedGenerationInput): Promise<void>;

  createJob(
    input: NormalizedGenerationInput
  ): Promise<ProviderJobResponse>;

  getJobStatus(
    externalJobId: string
  ): Promise<ProviderJobStatus>;

  cancelJob?(
    externalJobId: string
  ): Promise<void>;

  normalizeResult(
    rawResult: unknown
  ): Promise<NormalizedGenerationResult>;

  normalizeError(
    error: unknown
  ): NormalizedProviderError;
}

Provider’a özel request ve response tipleri adapter dışına çıkmamalıdır.

Uygulamanın diğer bölümleri fal.ai veya Runway’in ham cevap formatını bilmemelidir.

7. NORMALIZE EDİLMİŞ GENERATION INPUT

Bütün provider çağrılarından önce ortak bir input formatı oluşturulmalıdır.

type NormalizedGenerationInput = {
  generationId: string;
  userId: string;
  projectId: string;

  taskType:
    | "text-to-image"
    | "image-to-image"
    | "text-to-video"
    | "image-to-video"
    | "video-to-video"
    | "upscale"
    | "lip-sync";

  provider: string;
  modelKey: string;
  providerModelId: string;

  originalPrompt: string;
  enhancedPrompt?: string;
  negativePrompt?: string;

  inputAssets: Array<{
    assetId: string;
    url: string;
    type: "image" | "video" | "audio";
    role:
      | "start-frame"
      | "end-frame"
      | "character-reference"
      | "style-reference"
      | "source-video"
      | "audio";
  }>;

  settings: {
    aspectRatio?: string;
    resolution?: string;
    durationSeconds?: number;
    seed?: number;
    numberOfOutputs?: number;
    cameraMotion?: string;
    stylePreset?: string;
  };
};

Her provider adapter bu ortak inputu kendi API formatına çevirmelidir.

+ project_id
+ client_request_id

Aynı istek tekrar geldiğinde sistem:

12. RETRY VE FALLBACK KURALLARI

Her hata retry edilmemelidir.

Retry yapılabilecek hatalar
429 rate limit
502 bad gateway
503 service unavailable
504 timeout
geçici network hatası
Retry yapılmaması gereken hatalar
401 yanlış API anahtarı
403 yetki yok
400 geçersiz parametre
unsupported resolution
unsupported duration
moderation rejection
insufficient provider balance

Retry işlemleri exponential backoff kullanmalıdır.

Örnek:

30 saniye
2 dakika
5 dakika
15 dakika

Aynı provider üzerinde sınırlı retry yapılmalıdır.

Provider fallback yalnızca uyumlu model varsa uygulanmalıdır.

Kullanıcı belirli bir model seçmişse izinsiz şekilde başka modele geçirilmemelidir.
